# Quickstart: Geo-Visitation (011-geo-visitation)

Runnable validation that proves RF31–RF34 end to end. Artifacts referenced,
never duplicated: [data-model.md](data-model.md), [contracts/visitation.md](contracts/visitation.md).

## Prerequisites

- Python 3.13 environment with the project dependencies installed.
- Synthetic test env is provided by `tests/conftest.py` (in-memory SQLite,
  fixed `JWT_SECRET`/`SENSITIVE_DATA_KEY`) — never real credentials.

## Automated validation (the acceptance criteria of the spec)

```bash
# Haversine exact cases: inside, outside, border, antipodes, zero (FR-005)
pytest tests/unit/test_haversine.py -q

# Contract: camelCase request/response, status codes, ApiError payloads, tags
pytest tests/contract/test_visitation.py tests/contract/test_tourist_spots_radius.py -q

# Integration: mark → status → route progress seam; outside radius 409; idempotent repeat
pytest tests/integration/test_visitation_flow.py -q

# Schema-change path (0007) and boundaries
pytest tests/test_migrations.py tests/smoke/test_boundaries.py -q
```

All green ⇒ SC-002, SC-003, SC-004, SC-006 and the SC-005 AST gate are
satisfied by construction.

## Manual smoke (optional, via Swagger `/docs`)

1. `POST /api/v1/auth/tourists/...` register → login as tourist (Bearer
   token; the tourist id equals the account id — R7).
2. As admin, `POST` a spot with known coordinates, e.g.
   `latitude: -22.7271, longitude: -45.0366, toleranceRadiusM: 100`.
   (Omit `toleranceRadiusM` to exercise the 100 m global default.)
3. `POST /api/v1/visitation/spots/{spotId}/visits` with
   `{"latitude": -22.7266, "longitude": -45.0366}` (~55 m away) →
   **201** with `firstVisit: true`.
4. Repeat the same call → **201**, `firstVisit: false`,
   `routeOutcomes: []` (idempotent progress — FR-009), a new history row.
5. Call with coordinates ~5 km away → **409** `OUTSIDE_TOLERANCE_RADIUS`
   and a structured warning log in app output (SC-007); nothing persisted.
6. Same call with `latitude: 91` → **422** (schema, FR-013).
7. `GET /api/v1/visitation/visitations` → 2 rows;
   `GET /api/v1/visitation/visited-spots` → 1 item, `visitCount: 2`.
8. Bonus path: enroll the tourist in a route containing the spot (spec 009
   endpoints) and mark another route spot → `routeOutcomes` shows the
   `completionRate` rising; the last pending spot completes the enrollment
   exactly once (badge + redemption code generated by the seam).

Expected end state: history immutable, progress counted once per spot per
tourist, rejected attempts traceable in logs only.
